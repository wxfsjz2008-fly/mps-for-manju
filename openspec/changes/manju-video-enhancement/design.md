## Context

当前项目是一个全新的漫剧视频增强系统，需要从零开始构建。系统需要对接腾讯云的 COS（对象存储）和 MPS（媒体处理服务）来实现视频的存储和增强处理。

**当前状态**：空项目，需要完整搭建前后端架构

**约束条件**：
- 必须使用腾讯云 COS 存储视频文件
- 必须使用腾讯云 MPS 进行视频增强处理
- 需要支持并排播放和同屏对比两种视频对比模式
- 视频播放需要保持同步

**利益相关者**：
- 漫剧内容创作者：上传视频并查看增强效果
- 平台运营人员：管理和监控视频处理任务

## Goals / Non-Goals

**Goals:**
- 实现视频上传到腾讯云 COS 的完整流程
- 集成腾讯云 MPS 音视频增强模板进行视频处理
- 提供两种视频对比播放模式（并排播放、同屏对比）
- 实现任务状态跟踪和进度显示
- 提供简洁易用的 Web 界面

**Non-Goals:**
- 不实现视频剪辑功能
- 不实现批量视频处理（首期仅支持单视频）
- 不实现用户注册登录系统（首期简化）
- 不实现视频转码格式选择（使用固定的增强模板）

## Decisions

### 1. 技术栈选择

**前端**：React + TypeScript + Vite
- **理由**：React 生态成熟，TypeScript 提供类型安全，Vite 构建速度快
- **替代方案**：Vue.js（团队可能不熟悉），纯 HTML/JS（可维护性差）

**后端**：Node.js + Express + TypeScript
- **理由**：与前端技术栈统一，开发效率高，腾讯云 SDK 支持良好
- **替代方案**：Python Flask（需要切换语言），Go（学习成本高）

**数据库**：SQLite
- **理由**：轻量级，无需额外部署，适合单机部署的小型应用
- **替代方案**：MySQL（部署复杂），PostgreSQL（功能过剩）

### 2. 视频上传方案

**方案**：前端直传 COS + 服务端签名
- **理由**：减轻服务器带宽压力，上传速度更快
- 流程：前端请求签名 → 服务端生成临时密钥 → 前端直传 COS → 回调通知服务端
- **替代方案**：服务端中转上传（增加服务器压力和延迟）

### 3. MPS 任务触发方式

**方案**：服务端主动调用 MPS API
- **理由**：可控性强，便于任务状态管理
- 流程：视频上传完成 → 服务端创建 MPS 任务 → 轮询/回调获取结果
- **替代方案**：COS 触发器自动处理（灵活性差）

### 4. 视频对比播放实现

**并排播放**：
- 两个独立的 `<video>` 元素并排布局
- JavaScript 控制两个视频的播放同步
- 共享播放控制条（播放/暂停/进度条）
- 独立的音量控制

**同屏对比**：
- 使用 CSS `clip-path` 实现画面分割
- 两个 `<video>` 元素堆叠，通过 clip-path 控制显示区域
- 可拖动分割线，实时更新 clip-path 值
- 播放同步逻辑与并排播放相同

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| MPS 处理时间长导致用户等待 | 实现异步任务机制，提供进度提示和邮件/消息通知 |
| COS 直传安全风险 | 使用临时密钥（STS），设置合理的有效期和权限范围 |
| 视频同步播放可能出现偏差 | 实现定期同步校准机制，当偏差超过阈值时自动调整 |
| 大文件上传失败 | 实现分片上传和断点续传功能 |
| SQLite 并发性能限制 | 首期可接受，后续可平滑迁移到 MySQL/PostgreSQL |
