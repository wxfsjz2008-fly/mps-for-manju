## Context

本项目是一个漫剧视频增强系统，已实现视频上传、MPS 增强处理、任务管理和视频对比播放功能。视频文件存储在腾讯云 COS，所有视频 URL 都需要通过 STS 临时凭证生成签名才能访问。

**当前状态**：
- 系统已完整运行，视频上传、增强处理、对比播放均正常工作
- 视频播放使用签名 URL，签名有效期为 2 小时
- 前端已有获取签名 URL 的 API 调用逻辑

**约束条件**：
- 必须使用签名 URL 访问 COS 资源
- 下载功能应复用现有的签名机制
- 下载应在浏览器端触发，无需服务端中转文件流
- 文件名应体现是增强后的视频

**利益相关者**：
- 漫剧内容创作者：需要下载增强后的视频用于其他平台发布
- 视频运营人员：需要获取处理后的视频进行进一步编辑

## Goals / Non-Goals

**Goals:**
- 实现增强后视频的一键下载功能
- 提供友好的下载状态反馈（加载、下载中、错误）
- 下载文件名包含原文件名和"_增强"标识
- 支持大文件下载，不阻塞浏览器

**Non-Goals:**
- 不实现原视频下载（用户本地已有原视频）
- 不实现批量下载功能（首期仅支持单视频）
- 不实现下载进度显示（浏览器原生下载已有进度）
- 不实现断点续传（依赖浏览器原生能力）

## Decisions

### 1. 下载实现方案

**方案**：生成带 Content-Disposition 头的签名 URL + 前端创建隐藏 `<a>` 标签触发下载
- **理由**：
  - 无需服务端中转，减轻服务器压力
  - 利用浏览器原生下载管理器，体验更好
  - COS 签名 URL 支持设置 response-content-disposition 参数
- **替代方案**：
  - Fetch + Blob 下载（大文件可能导致内存溢出）
  - 服务端流式代理（增加服务器压力）

### 2. 后端接口设计

**方案**：新增专用下载 URL 接口 `POST /api/upload/download-url`
- **理由**：
  - 与现有的 `signed-url` 接口分离，职责单一
  - 可独立配置 Content-Disposition 头
  - 支持自定义下载文件名
- **接口参数**：
  - `url`: COS 原始 URL
  - `filename`: 期望的下载文件名
- **响应**：
  - `downloadUrl`: 带下载头的签名 URL
  - `expires`: 有效期（秒）

### 3. 前端交互设计

**方案**：在任务详情页"效果对比"区域下方添加独立的下载区块
- **理由**：
  - 下载功能与对比播放逻辑分离
  - 视觉上突出下载入口
  - 便于后续扩展（如多分辨率下载）
- **UI 元素**：
  - 下载按钮（渐变色，带下载图标）
  - 文件信息提示（文件名、大小）
  - 下载状态提示（准备中、已开始下载）

### 4. 文件命名规则

**方案**：`{原文件名（不含扩展名）}_增强.{扩展名}`
- **理由**：
  - 保留原文件名便于用户识别
  - "_增强"后缀明确表示是处理后的文件
  - 保持原扩展名确保文件关联正确
- **示例**：
  - 原文件：`漫剧第一集.mp4`
  - 下载文件：`漫剧第一集_增强.mp4`

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 签名 URL 过期导致下载失败 | 下载前实时生成签名 URL，设置较长有效期（如 1 小时） |
| 超大文件下载耗时长 | 提示用户下载可能需要时间，建议在网络良好时下载 |
| 部分浏览器可能阻止下载 | 使用用户点击事件直接触发，避免被拦截 |
